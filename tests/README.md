# Testing Infrastructure (`/tests`)

This directory is the centralized location for all testing-related code, Gherkin feature files, test runner configurations, and temporary test artifacts generated during test execution.

## Purpose and Artifact Isolation

In accordance with the **Strict Artifact Isolation** principle defined in `AGENTS.md` and tactically enforced by `.ai/rules/artifact-isolation.md`, this directory exists to keep the project root clean from temporary caches, reporting output, and build artifacts generated by testing or linting tools.

**Important:** The test results, caches, and reports generated in this directory are **not uploaded to the remote GitHub repository**. A strict rule in `.gitignore` (`tests/*` followed by `!tests/README.md`) explicitly ignores all contents within this directory *except* for this `README.md` file itself. 

Anytime an AI agent (or human) initializes or configures new tools (linters, formatters, test runners), they **must explicitly configure their output directories or cache locations to target the `tests/` directory** (e.g., `tests/.pytest_cache`, `tests/allure-results`).

## Directory Tree

The internal structure of this directory follows the project's Test-Driven Development (TDD) principles, categorizing tests into the following types:

```text
tests/
├── README.md               # This file (committed to Git)
├── integration/            # Integration Testing (Testing how modules/services work together)
│   ├── support/            # Shared integration fixtures, mocks, or API cassettes
│   └── test_*.ext          # Integration test suites
├── performance/            # Load and Performance Testing (Simulating user concurrency)
│   ├── scripts/            # Load scripts (e.g., k6, Locust)
│   └── payloads/           # Sample data bodies for load generation
├── ui/                     # End-to-End User Interface Testing (Testing the rendered UI)
│   ├── scripts/            # E2E test scripts (e.g., Playwright or Cypress)
│   └── snapshots/          # Visual regression baseline images
├── unit/                   # Unit Testing (Testing individual functions/classes)
│   ├── fixtures/           # Mock data and object factories for unit isolation
│   └── test_*.ext          # Unit test suites mirroring the /src tree
├── features/               # Behavior-Driven Development (BDD) Scenarios
│   ├── step_definitions/   # Code implementations mapping to Gherkin steps
│   └── *.feature           # Human-readable requirement scenario files
└── [Generated Artifacts]   # Ignored by Git (e.g. .pytest_cache/, allure-results/, coverage/)
```

## AI Agent Directives

1. When writing feature requirements or generating tests, AI agents must place new tests in their corresponding subdirectories (`features/` for Gherkin, `unit/` for unit tests, etc.).
2. When executing tests, AI agents must ensure all reporting outputs (e.g., HTML reports, coverage files) and temporary caches are dumped safely inside `/tests/...` instead of the project root.
3. For visual proof of passing tests, AI agents must document the passing raw CLI output in `docs/tasks/Task-[X]-Walkthrough.md`.
